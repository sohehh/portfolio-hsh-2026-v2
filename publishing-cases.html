프로젝트마다 화면과 요구사항은 다르지만, 구조를 정리하고 수정 내용을 전달할 때 아래 기준을 사용했습니다.

01

시안 분석 및 HTML구조 설계

시안을 보고 나눌 수 있을 만큼 그룹화합니다. 함께 움직이는 요소, 반복되는 요소, 의미가 다른 요소를 나눈 뒤 그에 맞는 시맨틱 태그와 일반 태그를 사용합니다.

  • 01비슷한 레이아웃을 가진 요소에는 CSS 스타일 재사용을 위해 동일한 클래스명을 사용합니다.
  • 02가독성·계층 구조·재사용성을 위해 BEM 방식으로 클래스명을 작성합니다.

03

JS작성 방법

이벤트 바인딩 대상에는 js- 접두사를 사용해 스타일 클래스와 구분합니다. JavaScript 파일에서는 기능 로직을 함수로 만들고, 이벤트에서는 필요한 함수를 호출하는 방식으로 작성합니다.

  • 01

    js- 접두사로 이벤트 대상임을 표시합니다.

  • 02

    Ajax 통신이나 DOM 로드 후 추가되는 인터랙션 요소에는
    $(document).on('click', '.js-button', ...)과 같은 이벤트 위임 방식을 사용합니다.

  • 03비슷한 기능끼리 JavaScript 파일을 나눠 관리합니다.

  • 04모바일 세로: 479px 이하

08

협업

순수 퍼블리싱과 기본 인터랙션 작업 후 Java 웹개발자에게 파일을 전달하는 방식으로 협업했습니다. 시안에서 구현 방법을 확인해야 하는 부분은 필요한 UI와 동작을 확인한 뒤 수정 범위와 적용 방식을 조율했습니다.

  • 01기존 파일에서 코드가 추가·변경되면 HTML·SCSS·CSS 파일 안에 수정 날짜 주석을 남깁니다.
  • 02수정 사항이 많은 경우에는 파일 전체를 전달하고 덮어쓰기 요청을 함께 남깁니다.
  • 03

    파일을 전달할 때는 변경된 파일명(index.html, index.css)을 나열하고, 필요한 수정 내용은 메신저로 함께 전달합니다.
